# ADR-0002：系统提示词单独传给模型，不放进对话历史

| 项目 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-15 |
| 作者 | Claude（技术负责人） |
| 评审 | maodesikeng-boop |

## 背景

chat-completions 接口里，系统提示词是消息列表的第一条（`role: "system"`）。我们的对话历史要保存、压缩、重启后恢复（[设计文档 01](../design/01-agent-loop.md) §4、§8、§12），所以要决定：系统提示词在我们自己的程序里放在哪里。

## 决策

- 对话历史（`Messages`）**只存用户、助手、工具三种消息**，系统提示词不放进历史。
- 模型接口 `ModelClient.complete` 多一个 `system` 参数，由调用方每次传入。
- 模型适配层（`model/` 里各家模型的实现）发请求时，负责把它放到消息列表的最前面。
- 系统提示词在程序启动时读取一次，之后不再改变（设计文档 01 §4.4：前缀必须稳定，才能命中缓存）。

## 备选方案与放弃理由

**把它作为历史里的第一条 `SystemMessage`**

- 好处：和接口格式一一对应，转换最简单。
- 放弃理由：历史里混进一条"不属于对话"的消息，以后压缩历史（设计文档 01 §8 的切分点）、开新对话、重启恢复时，都要特别保护它，不能被压缩掉，也不能重复；存进数据库时，每段对话还会存一份一模一样的提示词。
- 有的模型服务（比如 Anthropic 的接口）本来就要求系统提示词单独传，单独传的做法更容易对应。

## 后果

- 历史里只有真实发生过的对话，压缩、保存、恢复都不用对第一条做特殊处理。
- 所有 `ModelClient` 的实现（测试用的假模型、DeepSeek 适配）都要处理 `system` 参数。
- 要换提示词时，改的是启动时读取的那一处，不影响已经保存的对话。
